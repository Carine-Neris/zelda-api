# Developer Learning Context

Use this as a starting point for teaching style, not as evidence about the current repository. Confirm the actual stack and the developer's current familiarity as the work evolves.

## Starting profile

- The developer identifies as a mid-level software engineer.
- They have substantial prior experience with RPA and are strengthening their understanding of web application architecture and end-to-end request lifecycles.
- Their recent hands-on context includes Python, FastAPI, Docker, and PostgreSQL.
- They are familiar with Django and find comparisons to Django useful when explaining analogous ideas.

## How to use this context

- Do not assume the current project uses Python, FastAPI, Docker, PostgreSQL, or Django. Inspect the repository first.
- When explaining a concept, use a Django comparison only if it is accurate and clarifies the concept. For example, compare request handlers, validation/schema boundaries, ORM models, middleware, or dependency injection only where the concepts actually align.
- Do not force a Django analogy onto frontend, browser, HTTP, distributed-systems, or framework-specific concepts where it would confuse more than help.
- Build on the developer's existing software experience. Explain unfamiliar web-specific concepts without restarting from basic programming concepts.
- Gradually reduce scaffolding as understanding improves. The goal is independent reasoning, not permanent step-by-step dependence.
